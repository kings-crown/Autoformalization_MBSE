# Autoformalization_MBSE Comprehensive Setup, Run, and Validation Guide

Last updated: 2026-03-20

This document consolidates:
- how the current pipeline works (`evidence`, `domain` and `architecture` SysML modes),
- what `sysml-compile` does and does not prove,
- complete environment setup for Z3, SysML v2, and SysIDE,
- stage-by-stage terminal validation so you can verify each subsystem independently.

---

## 1. Scope and Outcome

This guide is designed to get you to a reproducible workflow where you can:
1. Translate requirements into intermediate formal artifacts (TLR + SMT).
2. Validate SAT/UNSAT expectations with Z3.
3. Generate SysML in one of:
   - `--sysml-mode evidence` (traceability/evidence scaffold), or
   - `--sysml-mode architecture` (first-class parts/ports/messages/states/transitions/connections + requirements wrappers), or
   - `--sysml-mode domain` (domain model + split traceability output path).
4. Optionally load-check the generated SysML with the SysML interactive kernel (`sysml-compile` stage).
5. Validate textual models and visualize them in VS Code using SysIDE tools.

## 2. Repository-Specific Facts (Current State)

### 2.1 Pipeline entrypoint
- `scripts/requirements_pipeline.py`

### 2.2 SysML modes
- `--sysml-mode evidence`
  - Emits `RequirementContext`, `SolverEvidence`, `AutoGeneratedRequirement`, `SmtValidationSummary`, `EvidenceOverview`.
  - Primary value: documentation + traceability + solver evidence binding.
- `--sysml-mode architecture`
  - Emits first-class model structure and behavior based on Domain IR:
    - workflow components as `part def`s,
    - typed ports and signals,
    - messages,
    - state machine and transitions,
    - constraints and top-level connections,
    - synthesized requirement wrappers and analysis view.
- `--sysml-mode domain`
  - Emits domain-oriented SysML plus a separate traceability SysML module.
  - Produces both Domain IR and Traceability IR JSON artefacts.

### 2.3 Artefacts
The pipeline emits:
- `<prefix>_translate.json`
- `<prefix>_tlr.json` (if TLR present)
- `<prefix>_sat.smt2`
- `<prefix>_unsat.smt2`
- `<sysml-output>`
- `<prefix>_domain_ir.json` (architecture and domain modes)
- `<prefix>_traceability_ir.json` (domain mode)
- `<traceability-output>` (domain mode)

### 2.4 `sysml-compile` behavior
`sysml-compile` is currently **work in progress**.

When enabled, the compile step behaves as a kernel load check:
- launches Java class `org.omg.sysml.interactive.SysMLInteractive`,
- sends `load <sysml file>` then exit command,
- fails on timeout or non-zero exit code.

Recommended workflow at this stage:
- treat `sysml-compile` as experimental,
- generate SysML with `--skip-sysml-compile` when needed,
- validate and visualize the generated model in SysIDE.

### 2.5 Prototype input contract

At this prototype stage, treat CSV as the required requirements input format for pipeline runs.
Non-CSV inputs (`.pdf`, `.txt`, `.json`) are not supported by the current CLI contract.

Use:
- `examples/pure/eirene_fun7_harvest_requirements_top10.csv` (baseline)
- `examples/pure/eirene_fun7_harvest_requirements_top11.csv` (baseline + contradiction/ambiguity injection)

### 2.6 Prototype provider caveat

At this stage, the validated end-to-end workflow in this repository is Codex-focused (`--llm-provider codex`).
Other provider paths should be treated as experimental until additional validation coverage is added.

## 3. What `sysml-compile` Validates vs What It Does Not

### 3.1 What it validates
1. The `.sysml` file can be loaded by the configured SysML interactive kernel.
2. Gross syntax and load-time model issues that prevent kernel load.
3. Environment wiring: Java + kernel JAR + runtime invocation.

### 3.2 What it does not validate
1. Domain correctness (whether architecture behavior is the right one).
2. Completeness/adequacy of requirements formalization.
3. Proof that generated constraints capture stakeholder intent.
4. End-to-end safety/liveness satisfaction in your real system.

Interpretation: `sysml-compile` is optional and experimental in the current prototype.

## 5. Install and Validate Z3

There are several valid ways; pick one and standardize.

## 5.1 Option A (recommended): native binary from official Z3 releases

1. Go to official Z3 repository releases:
   - https://github.com/Z3Prover/z3/releases
2. Download Linux x64 package for your platform.
3. Extract and place `z3` on PATH, or keep it local and export `Z3_PATH`.

Example local-path setup:

```bash
mkdir -p "$HOME/tools/z3"
# extract downloaded archive into $HOME/tools/z3/z3-<version>
export Z3_PATH="$HOME/tools/z3/z3-<version>/bin/z3"
"$Z3_PATH" -version
```

## 5.2 Option B: Python wrapper

```bash
python3 -m pip install --user z3-solver
python3 - <<'PY'
import z3
print(z3.get_version_string())
PY
```

Note: `z3-solver` gives Python bindings. For CLI workflows in this repo, prefer a native `z3` binary as well.

## 5.3 Option C: package manager install (Linux)

Distro package names vary. Example (Ubuntu/Debian):

```bash
sudo apt-get update
sudo apt-get install -y z3
z3 -version
```

If package version lags too much, use Option A.

## 5.4 Repo-level Z3 validation (from generated artifacts)

The `out/` directory is runtime-generated. In a fresh clone, generate a SAT/UNSAT pair first:

```bash
python3 scripts/requirements_pipeline.py \
  --statement examples/pure/eirene_fun7_harvest_requirements_top10.csv \
  --output-prefix out/validate_z3 \
  --sysml-output out/validate_z3.sysml \
  --llm-provider codex \
  --model gpt-5.4 \
  --skip-intent-formalization \
  --skip-sysml-compile
```

Then validate the generated SMT files with Z3:

```bash
z3 out/validate_z3_sat.smt2
z3 out/validate_z3_unsat.smt2
```

Expected:
- SAT file returns `sat`
- UNSAT file returns `unsat`

## 7. Install and Use SysIDE (VS Code) for Validation and Visualization

There are two tracks:
1. **Syside Editor** (free): textual support + validation.
2. **Syside Modeler** (licensed): includes richer visualization workflow.

## 7.1 Syside Editor (free) - validation-centric

Docs:
- https://docs.sensmetry.com/editor/index.html
- https://docs.sensmetry.com/editor/install.html

Install from VS Code Marketplace:
1. Open VS Code.
2. Extensions (`Ctrl/Cmd+Shift+X`).
3. Search `Syside Editor`.
4. Install **Syside Editor by Sensmetry** (`sensmetry.syside-editor`).

Verification flow:
1. Create `example.sysml`.
2. Paste sample model from Syside install docs.
3. Confirm live diagnostics appear for intentional errors.
4. Fix model and confirm diagnostics disappear.

This gives immediate syntax/semantic feedback while editing generated models.

## 7.2 Syside Modeler (licensed) - visualization-centric

Docs:
- https://docs.sensmetry.com/latest/modeler/install.html

Important note from docs:
- uninstall Syside Editor before using Syside Modeler to avoid conflicts.

Install steps (Marketplace path):
1. Install `Syside Modeler` extension.
2. Run command `Syside Modeler: Install Syside Tools`.
3. Enter license key when prompted.

Visualization check:
1. Open `example.sysml`.
2. Use `Ctrl+Shift+V` (Windows/Linux) or `Cmd+Shift+V` (macOS), or `Visualize current file` via Syside UI.
3. Confirm diagram renders.

If prompt says Python/Java missing, allow tool install and rerun visualization command.

## 11. Common Failure Modes and Precise Fixes

1. `OPENAI_API_KEY is not set`
   - Cause: OpenAI provider selected without key.
   - Fix: export key, or use `--llm-provider codex`.

2. `codex exec timed out after ...`
   - Cause: generation exceeded timeout.
   - Fix: increase `CODEX_EXEC_TIMEOUT`, optionally lower reasoning effort.

3. `conda: command not found`
   - Cause: conda not on PATH.
   - Fix: use full path (`$HOME/miniforge3/bin/conda`) or shell init.

4. `SysML kernel JAR not found`
   - Cause: bad jar path or env mismatch.
   - Fix: set `SYSML_KERNEL_JAR` explicitly.

5. `sysml-compile` warning with generated artifacts present
   - Cause: load-check failed but hard-fail not requested.
   - Fix: inspect warning text, keep `--skip-sysml-compile` in normal workflow, and validate/visualize generated models in SysIDE.

6. Syside visualization unavailable in Editor-only setup
   - Cause: rich visualization is Modeler workflow.
   - Fix: install/activate Syside Modeler (licensed), then run visualize command.
